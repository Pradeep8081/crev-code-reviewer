Executive Summary for Evaluators & Professors:
C-rev is a full-stack, developer-first code inspection and runtime execution platform designed with a clean LeetCode-inspired interface. Unlike generic text generators, C-rev physically executes code inside a controlled child-process sandbox (supporting Python and JavaScript/TypeScript), measures real execution times (in milliseconds), intercepts syntax and runtime crashes, and performs automated senior peer code reviews with exact word-level inline diff replacement.

🎯 1. Project Purpose: Kis Kaam Ke Liye Bana Hai?

In software engineering education and professional programming, developers face three major bottlenecks:

  1. Vague Error Messages: Standard compilers or interpreters often throw cryptic stack traces (e.g. TypeError: Cannot read property 'tier' of undefined or ZeroDivisionError: division by zero) without explaining why the bug occurred in plain everyday terms.
  2. Lack of Human-Readable Peer Code Review: Students and junior programmers rarely get access to senior software engineers to review their code quality, performance time complexity ($O(N)$ vs $O(N^2)$), and edge case handling.
  3. Manual & Risky Debugging: Developers spend hours guessing fixes, frequently introducing new regression bugs in the process.
✅
C-rev solves this by providing:
• Real Runtime Execution: Run Python & JS with live stdout/stderr console output.
• Automated Line-by-Line Diagnosis: Highlights the exact faulty line and word in the editor.
• 1-Click Quick Remediation: Fixes the bug in the code editor with a single tap.
• Plain-Language Verdict: Generates a clean 0–10 code score, time/memory complexity analysis, and edge case breakdown in simple words without academic jargon.

🔄 3. How It Works: Step-by-Step Execution Workflow

Step 1: Code Input & Auto-Detection

The user pastes or uploads source code. The regex-based language detector (detectLanguage()) evaluates keywords, syntax signatures (e.g. def / import for Python, const / async for JS, #include for C++) and immediately adjusts editor syntax highlighting.

Step 2: Sandbox Execution (Run Code)

When the user clicks the green "Run" button:

  • Frontend sends a POST request with the source code payload to /ai/run-code.
  • The backend creates a random isolated temp file (e.g. crev_py_1727339_abc.py).
  • Spawns a child process to execute the code using native interpreters.
  • If execution succeeds with exit code 0, standard terminal output is returned with execution duration in milliseconds.
  • If an exception occurs, the error trace is intercepted and routed to the Diagnostic Analyzer.

Step 3: Bug Diagnosis & Word-Level Diff Extraction

Upon error detection, the engine evaluates the faulty line and returns a structured JSON schema: 

{
  "lineNumber": 14,
  "bugLocation": "price / discount_rate",
  "faultySnippet": "discounted = price / discount_rate",
  "fixedSnippet": "discounted = price / discount_rate if discount_rate != 0 else 0",
  "cause": "Division by zero occurs because discount_rate evaluates to 0.",
  "solution": "Add an explicit non-zero guard check before division.",
  "fixedCode": "... complete runnable source code ..."
}

Step 4: 1-Click Code Replacement in Editor

The frontend receives the diff object. When the developer clicks "Apply Quick Fix":

  • The editor code state is atomically replaced with the corrected source code.
  • The exact line in the editor gutter is highlighted in green with a checkmark badge.
  • The user can immediately click "Run Fixed Code" to verify that the program now exits with status 0.

🎓 5. Professor & Viva Voce Examination Defense Guide

Use these exact explanations during your college presentation, external viva, or project review:

Q1: "Did you just call an AI API, or is there real programming involved?"
Your Answer:
"No, Sir. The project is a complete full-stack software system. The core execution engine is built with Node.js and uses Linux OS child processes (`child_process.exec`) with temporary file sandboxing to physically run Python and JavaScript code on the server, capturing stdout, stderr, execution time in milliseconds, and exit codes. The AI engine is used selectively as an intelligent diagnostic layer to structure error explanations and suggest defensive code improvements, while the entire client-side diffing, state management, line-highlighting, and workspace file system are built by me in React."
Q2: "What happens if a student writes an infinite loop like while(True)?"
Your Answer:
"I implemented an Execution Guard with a strict 6,000 millisecond timeout at the process level. If a script exceeds 6 seconds, the Node.js child process automatically sends a `SIGTERM` signal, terminates the runaway process, unlinks the temporary file from disk, and returns a graceful Timeout Error to the frontend without crashing the server."
Q3: "How does the 1-click Quick Fix work without losing other code?"
Your Answer:
"I developed a custom token-difference algorithm (`getChangedTokenInfo()`) in JavaScript. It computes prefix and suffix string invariants between the original erroneous line and the corrected replacement, isolates the exact token that caused the bug, and applies an atomic state update in the React workspace while providing an undo/revert stack."
Q4: "Where and how is the project deployed in production?"
Your Answer:
"The project uses a Production Microservices Architecture. The React frontend is deployed on Vercel Edge CDN for global sub-50ms latency. The backend is deployed on Render as a persistent Linux Web Service running Node.js and Python. Both services communicate securely over HTTPS with CORS protection and automated CI/CD from my GitHub repository (`Pradeep8081/crev-code-reviewer`)."
